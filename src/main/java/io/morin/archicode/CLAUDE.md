# The command line (Java)

Static analysis, the workspace file, facets, errors and warnings, the schema of the manifests, `guide`, `init`, and the reading of mistakes. How the editor page reads YAML and saves is in `src/main/editor/persistence/CLAUDE.md`. The decisions behind these rules are in `docs/wav/`.

## Static analysis (PMD)

- PMD 7.28.0 through `maven-pmd-plugin` 3.28.0, both pinned in `pom.xml` (no server, no secret). The `check` goal is bound to `verify`: the job `Java` of CI runs it with `./mvnw verify` and a finding fails the build. There is no baseline file: a finding is fixed, or its rule is turned off in the ruleset with its count and its reason.
- The ruleset is `src/main/pmd/ruleset.xml`: PMD's `quickstart` set minus `ControlStatementBraces`, `AvoidUsingHardCodedIP`, `LocalVariableNamingConventions` and `UselessParentheses` (Prettier writes those parentheses), with the properties of four rules adjusted (`LooseCoupling`, `GuardLogStatement`, `CloseResource`, `CompareObjectsWithEquals`), each with its reason in the file.
- The command to run is `./mvnw test-compile pmd:check`: PMD needs the compiled classes, test classes included, to resolve types, and without `test-compile` the findings differ. It reports in `target/pmd.xml`; a file it cannot analyse fails it (`skipPmdError` is false). A build that leaves the test classes out (`-Dmaven.test.skip`) must pass `-Dpmd.skip=true`: the two publishing builds of the `Build` job do, because `Java` has run it on the same sources (without the skip it reported a `NonExhaustiveSwitch` on `main` that `verify` does not). The Native job skips it (`pmd.skip` in the `native` profile). The sources the chicory compiler writes (`ViewpointKernelModule*`) are excluded. SonarLint stays the author's own choice in the IDE, outside the build.

## The workspace file

- `.archicode.yaml` is the hidden file that marks a folder as a workspace and holds its `settings`. Only the default of `-w` / `--workspace` names it (`cli/ArchiCode.java`); `-w workspace.yaml` as an explicit path still works.
- A folder that has `workspace.yaml` and no `.archicode.yaml` gets one sentence, the same in both tools (`WorkspaceFactory.FORMER_NAME_SENTENCE`; `FORMER_WORKSPACE_FILE_SENTENCE` in the page): rename it (`git mv workspace.yaml .archicode.yaml`) or pass `-w workspace.yaml`. The command line prints it as the one `error:` line (exit 1, also from `editor serve`) before anything is loaded; the editor shows it as the reason the folder cannot be opened. Cases: `workspace-file-name-cases.json`, read by `WorkspaceFileNameTest` and `workspace-file-name.test.js`.
- Failing to have the file is typed: `WorkspaceFileException` (a subclass of `ArchiCodeException`, `workspace/`) with a `Reason`: `MISSING` (no regular file, or a folder), `FORMER_NAME`, `UNREADABLE` (the file system refuses it: ``error: the workspace file `<path>` cannot be read: permission denied``, one line, exit 1). It is raised in `WorkspaceFactory.read` and by `editor serve`. `ErrorOutput` never rewords a message; a test pins that a message which names `.archicode.yaml` for another reason prints as it is.
- The editor keeps the same kinds in `AppState.fatalErrorKind` (`setFatalError(message, kind)`): `'unreadable'`, `'renamed'`, and none for anything read and found wrong (an unknown key, invalid YAML, a document that is not a mapping, `settings.plateaus`, a path or a facet name the settings refuse), which are told as they are. The landing card words only `'unreadable'` as "`.archicode.yaml` could not be read in “folder”" (with the hint), says the `'renamed'` sentence as it is, and the list of remembered folders notes both (`landingScreenConfig`, `showRememberedFolders`). The `expect.failure` of each case is `unreadable`, `renamed` or `content`.
- Discovery finds it as the workspace and never reads it as a manifest, with or without `/**` (hidden, so left out below a `/**` path; `ManifestDiscovery.WORKSPACE_FILE_NAME`, `readManifestFolder`; D37 and D38 of `discovery-cases.json`). `editor serve` lists and serves it at the root of the folder only (`EditorHttpServer.WORKSPACE_FILE`; every other hidden entry is refused). The old name stays pinned only by those cases and by `delete-plateau-as-released.test.js`. `CustomRenderingTest` reads the author's git-ignored `.custom/.archicode.yaml`, else `.custom/workspace.yaml`.

## Facets

- Facets (`settings.facets`) are evaluated by the kernel as standard JSONPath (RFC 9535, `serde_json_path`): `WorkspaceFactory` hands it the JSON of the workspace (`apply_facet`), the editor hands it the elements of the view. Jayway is still used by the `query` commands only. An action that removes an element removes in the same step what points at it (relationships, `uses`, `applications`), so a facet can hide an element without a `dangling reference`; it says nothing about it.
- The Jayway dialect (`anyof`, `noneof`, `== null`, `!= null`) is refused by the kernel (`facet::refuse_legacy`, in `apply_facet`, `compute` and `quiet`) with one sentence that names the standard form (``the facet path `P` uses `@.qualifiers anyof ['a']`, which is not JSONPath (RFC 9535) and is no longer read: write `@.qualifiers[?(@ == 'a')]` ``). The command line prints `error: facet <name>: ...` (exit 1); the editor shows it as the error of the view. Cases: `facet-dialect-cases.json`, read by the kernel's tests, `ViewpointKernelTest` and `conformance.test.js`.
- The name of a facet is one folder name: it goes as written into `views-<plateau>-<facet>` and `<NN>-<view>-<facet>` (`directory-name-template`). A name that is empty, `.`, `..`, holds `/`, `\`, a NUL or another control character, or one of `<>:"|?*`, or ends with a dot or a space, is refused and never rewritten, with one sentence per facet in the order of the file, the first reason found from the left (``the facet name `a/b` cannot be the name of a folder: it holds `/`, which separates the folders of a path (write a plain word, such as `journey`)``; a control character is written `\u0000`). The reserved Windows device names are not looked at.
- The command line refuses such a name at the load, after the `manifests.paths` check and before any manifest is read, so every command that loads the workspace says it (not `plateau list`): `FacetNames`, `WorkspaceFactory.requireFacetsThatAreFolders`. The editor stops at the same place with the same words (`facetNameProblem`, `facetNameProblems`; *Add facet* refuses too, `validateFacetName`). Cases: N94 to N104 of `negative-cases.json` (whole workspaces, run on four commands in N97) and `facet-name-cases.json` (name by name, accepted names too), read by `FacetNamesTest` and `facet-names.test.js`.

## Errors and warnings

- `cli/ErrorOutput` is the error path of every command (installed by `cli/CommandLineConfiguration`, and by the tests through `errorOutput.install(commandLine)`). A failure the author can act on (`ArchiCodeException`, an invalid or absent manifest or workspace file, a file or folder the file system refuses, a port in use; the most precise cause in the chain wins; an `IOException` that is not about a file is a bug) is `error: <one line>` with exit 1 and no stack trace. A usage error keeps picocli's code 2. `archicode diff --fail-on` exits with 3 (`ErrorOutput.CHANGES_FOUND`). An unexpected exception keeps its trace.
- A view named with `views generate -i` whose element a facet removes (in the views of the plateau or of its comparison) is one line before the first folder is written, ``error: the view `v` cannot be drawn: it names `x`, which the facet `f` removes``, exit 1, nothing written (`GenerateViewsCommand.requireViewsKeepTheirElement`, only when `-i` is given). An entry of a map that a facet removes is dropped without a word, and an element the plateau lacks is a skip with a warning. `ViewRemovedByFacetTest`, `ViewsAndQueriesIT`.
- Nothing uses `log.warn` for the user (`quarkus.log.level=ERROR` hides it). A warning goes through the `Warnings` bean (`warn`, `warnAll`), de-duplicated, and `ErrorOutput` prints it as `warning: ...` when the command ends (before the error, if it fails). A story step on an undeclared view, a skipped viewpoint, `Comparison.getWarnings()` and `StateTags` use it.
- The editor refuses the same manifests and `.archicode.yaml` with the same sentences: `READ_SCHEMA` in the page holds the keys, shapes and kinds of each class, and `EditorReadSchemaTest` compares it with the classes, so a class that gains a key fails until the page knows it. The cases both tools run are in `src/test/resources/brightcart/negative-cases.json`. `AbstractElement.replaces` is read as a `Replaces` (a set that also keeps the JSON as written) which `KernelGraph` hands to the kernel, so the kernel's warnings about a duplicate, a non-reference entry and a non-list fire from the command line.
- Empty or odd values are read alike by both tools (`MapperFactory.reading`; N59 to N77 of `negative-cases.json`, M65 to M80 of `plateau-model-cases.json`): a key with nothing after it and a list item with no value are absent, so the default is read (`global-enabled:` empty is `true`; a `JsonNode` such as a patch `value` keeps its null; a map keeps a null value). The page leaves the item out of `elements`, `paths`, `qualifiers`, `applications`, `uses` and `relationships` (N87). Each relationship of a record keeps `fileIndex`, its place in the list of the file, which the element forms address it by (`data-index`); the Remove button of a qualifier, an application or a use carries the place of its pill among the pills drawn, and the handler removes the same-numbered item that has a value in the list it edits (`withoutNthPresent`; `remove-buttons-address-the-file.test.js`).
- More of the same: a manifest that holds only `null` has no header; an empty or comment-only `.archicode.yaml` is the default workspace; `settings.current: ""` names no plateau; a number is no value of an enum (`header.kind: 5`, `layer: 1`); an item of `elements` that is a list is the wrong shape.
- The keys of `settings.facets` are kebab-case (`global-enabled`, `directory-name-template`, `hide-unlinked`, `json-path`). The camel-case spelling is not read: it is the one `unknown key` line completed with the key to write (``unknown key `hideUnlinked`, write `hide-unlinked` (known: ...) at `settings.facets.customs[0].hideUnlinked` ``; N76 and N91 to N93). `Patch` still reads `json_path` as an alias of `json-path`.
- The header fields the command line types as text (`parent`, `plateau`, `version`) are the text as written: `parent: yes` is the reference `yes` in both tools (`parseYamlAsModel` in the page). The content reads a YAML 1.1 boolean as the boolean in both (`id: yes` is `true`).

## Numbers in YAML

- Plain scalars that YAML 1.1 reads as numbers are read alike by both tools; the cases (Y125 to Y279 for tagged scalars and where a refused scalar is met) are `yaml-number-cases.json` (expectations written from the command line), read by `YamlOneDotOneNumbersTest` and `yaml-numbers.test.js`. The command line (Jackson over SnakeYAML) reads `0`, signed decimals, octals (`010` is 8; `09` is no octal), `0x1F`, `0b11`, `_` in the digits, and numbers with a dot or an exponent (`.5`, `1.`, `5.0`, `1e3`, `1_0.5`). It refuses `.inf`, `.nan` and `._` (`Malformed numeric value '.inf'`, ``at `content` `` or ``at `header.parent` `` in a manifest, no place in `.archicode.yaml`).
- What it makes of them depends on the target. A text field of the content of a manifest gets the text Java prints (`id: 010` is the reference `8`, `1.50` is `1.5`, `1e3` is `1000.0`, `5.0` is `5.0`, `1e22` is `1.0E22`, an integer beyond 2^53 its digits). A text field of `.archicode.yaml` and a header field (`parent`, `plateau`, `version`) get the text as written (`parent: 0` is the reference `0.c`). A whole number accepts any of them (a float is truncated; out of range is `Numeric value (<as written>) out of range of int ...`). A boolean accepts the whole ones (a float is `wrong shape (found a number)`). An enum says the number (`layer: 0x1F` is unrecognized `"31"`). A quoted scalar is a text everywhere.
- Where a refused scalar is met is the same in both: the content of a manifest is decoded whole, so a scalar it refuses anywhere in it is the first thing said (``Malformed numeric value '.inf' at `content` ``), while the header is read key by key (`foo: .inf` under an unknown key of the header is the unknown key; `parent: .inf` is ``... at `header.parent` ``). Tagged scalars (`!!int`, `!!float`, `!!binary`) are read by the page as the command line reads them; see `src/main/editor/persistence/CLAUDE.md`.
- Known differences, pinned: the page does not tell the line and the column of a file; a float that JavaScript prints another way than Java (`5.0`, `1e3`) is the text Java prints in a field of any shape, so a patch `value` of `5.0` is the text `"5.0"` where the command line holds a number (Y252, Y253, `editor-reads-like-cli.test.js`); a `!!binary` text in a whole number, a boolean or an enum is the wrong shape (found a string) for the page and `Cannot deserialize value of type ... from Embedded Object value` for the command line (Y226); the digits of other scripts that Java reads in a tagged integer, a code point Java does not define in a binary text and a hexadecimal float that is not a normal number are not read like Java.

## The schema of the manifests

- `archicode query schemas manifest` gives the envelope (`Manifest`: `header` and `content`) and, under `kinds` (keyed by the `header.kind` ids), the schema of the content of each of the ten kinds. `manifest/ManifestSchema` generates it from the classes: Jackson's JSON-Schema generator on `ManifestKind.getType()`, completed by introspection (`additionalProperties: false` for a class that does not ignore unknown keys, `aliases` from `@JsonAlias`, `required` from `@JsonProperty(required)` or `@Required`, the rule of an id and the form of a reference from `@Identifier` and `@Reference`, enums sorted and said to be read in any case). Nothing is typed by hand.
- Each element kind also says `layer`, `holds` (the kinds it can hold, from `Parent#elementType()` and `Nesting.kindsHeldBy`) and `heldAtTheTop` (`Nesting.holdsAtTheTop`). The `elements` of a parent is a union, in the `type` of its items, of `{"$ref": "#/nested/<kind>"}`; `nested` has the form of each element kind as written under a parent (the content plus a required `kind`), so the recursion is a pointer.
- `query schemas workspace` is byte for byte that of 0.19.0 (golden `src/test/resources/schemas/workspace.schema.json`); `@Required` exists because adding `@JsonProperty(required)` to `View`, `Story` and `Plateau` would have moved it. The dialect is Jackson's, close to draft 3 (`"required": true` on the property, no `oneOf`), so a content that depends on `header.kind` is the ten schemas of `kinds`, chosen by the reader. The singular `relationship.qualifier` (added by Lombok's `@Singular`) is not in the schema, because it has no getter.
- What a schema cannot say is `src/test/resources/schemas/not-expressible.json`, one entry per limit with the cases of `negative-cases.json` that run it.
- Tests: `ManifestSchemaTest` (the golden file `manifest.schema.json`, the same bytes every time), `EditorReadSchemaTest.shouldSayWhatTheEditorTableSays` (the schema equals `READ_SCHEMA`), `ManifestSchemaCorpusTest` with `ManifestCorpus` and `SchemaChecker` (the 421 manifests the repository ships conform, the cases of `negative-cases.json` that load conform, the structural ones are refused, every other refusal is in the table), `SchemasIT`. A class change that changes the schema changes the golden file in the same commit: `archicode query schemas manifest > src/test/resources/schemas/manifest.schema.json`.

## The guide

- `archicode guide` (`cli/GuideCommand`, `cli/Guide`) prints Markdown for an agent that has only the binary. It loads no workspace (`-w` is not looked at), reads nothing outside the application and is the same from any folder and any run. The first line is `archicode guide <version>` (`quarkus.application.version`, the version of the pom).
- Two sections are generated: the manifests (`Guide.kinds()`: the header and each of the ten kinds with keys, required keys, enums, shapes and nesting, from `ManifestSchema`; the value types `element-id`, `plateau-id`, `reference` and `view-id` come from the descriptions of `@Identifier` and `@Reference`) and the commands (`Guide.commands()`: every command and option with the first sentence of its help, at most 220 characters; `-h` and `-w` are said once). The rest is `src/main/resources/guide/guide.md` (`guide/**` is in `quarkus.native.resources.includes`; `{{kinds}}` and `{{commands}}` mark the generated parts): the loop, the exit codes (1, 2, 3), the `error:` and `warning:` lines, the fact that only the first error is reported (no `validate`), `.archicode.yaml`, the conventions an agent cannot guess, and a small workspace made of `yaml` blocks that start with `# file: <path>` and `bash` blocks with `# exit <n>`.
- The properties of a view are `any` in the schema because the code reads them by name (`KernelViewpointFactory`: `element`; for a map `pinned`, `hidden`, `opened`; for a map of the technology layer `applications` and `relationships`, both drawn unless `false`). The guide has them in a table and says the keys the editor writes and the command line ignores (`facet`, `hide-unlinked`, `labels`, `qualifiers`, `descriptions`, `wrap`) are ignored; `GuideViewPropertiesTest` holds the table to the code (each key the guide says is read changes the drawn file, each it says is ignored changes nothing, and every key of `VIEW_PROPERTY_ORDER`, `MAP_PARTS` and `DIAGRAM_SHOW_NAMES` of the editor is in the guide).
- Tests: `GuideTest` (every command, option and kind; the first line; two runs give the same bytes, equal to `src/test/resources/guide/golden.md` with `@VERSION@` for the version; a 30 KB budget; the guide's workspace is written from its blocks and its commands run with the exit codes it gives; the golden file is not named `guide.md` because a test resource of that name would hide the application's), `GuideCorpusTest` (the manifests of the guide are `ManifestCorpus.guide` and conform to the schema), `GuideIT`. Regenerate the golden file after a change to the resource, a command or a kind: `archicode guide | sed '1s/.*/archicode guide @VERSION@/' > src/test/resources/guide/golden.md`. A command, an option or a key that changes the guide changes the golden file in the same commit.

## init

- `archicode init [FOLDER]` (`cli/InitCommand`) writes `.archicode.yaml` and three manifests (a person `customer`, a system `shop` with the container `web`, one relationship from `customer` to `shop.web`, and the saved overview view `shop_overview` of `shop` with `properties: {element: shop}`) from `src/main/resources/init/` (`archicode.yaml` is written as `.archicode.yaml`; `init/**` is in `quarkus.native.resources.includes`, `InitCommand` in `reflect-config.json`). It creates FOLDER (default: the current folder) and adds `/views*/` to `.gitignore` (created, or appended to once; nothing is removed).
- It never overwrites: a folder that already holds `.archicode.yaml` or one of the manifests is one `error:` line (`ArchiCodeException`, exit 1) and nothing is written. It prints what it wrote and the commands to run next (`query graph`, `views generate`; the saved view is drawn with `views generate -i shop_overview`).
- Tests: `InitTest` (writes, loads, draws, refuses, the `.gitignore` cases), `InitCorpusTest` (`ManifestCorpus.init`), `init-workspace.test.js` (the editor opens the resources), `InitIT` (the jar and the native runner). The guide's section "Starting from nothing" and `golden.md` say how to start (a `sh` block, because `GuideTest` runs the `bash` blocks).

## No stack trace for a mistake in one key

- A saved view or a story step with no `properties` key is the same mistake as `properties: {}`: one line, ``error: the view `v` has no element: write the reference of one in `properties.element` `` (`KernelViewpointFactory.create`; a map needs no element and is drawn). The editor says `This view has no element.` for both (`library-view-edit.test.js`); `ViewWithoutPropertiesTest`.
- `MistakeSweepTest` (`src/test/java/io/morin/archicode/doc`) copies every shipped workspace, removes one key, empties one list or map, or sets one key to `null` in a manifest (header and content, three levels deep, in memory), and runs `query graph`, `views generate` and, for a view or a story, `views generate -i` or `stories generate`. Each verdict is a success or `error:` lines with exit 1; a stack trace, `unexpected` or another exit fails, except the cases of `src/test/resources/known-traces.json` (each with an issue; empty; a listed case that no longer fails fails the test). The build sweeps the richest manifest of each kind of each workspace (1,190 mutated workspaces, about three minutes); `-Darchicode.sweep.all=true` sweeps all of them (8,611, about eight minutes: run it when a loader changes); `-Darchicode.sweep.only=<part of the workspace path>` sweeps one workspace.

## A dangling reference says where it is

- A relationship `destination`, a `uses` entry or a hosted application that names no element is one sentence in both tools, with plateaus or without: ``` `shop.web` has a relationship towards `nowhere`, which does not exist, in `manifests/shop.yaml` at `relationships[0].destination` ``` (`uses[1]` and `applications[0]` for the others). A layered workspace says ``in the plateau `p`, `` first and counts the others (`(1 more element of the plateau points at it)`); one sentence for each missing reference.
- `workspace/DanglingReferences` finds and words them (`find`, `sentences`, `about`). `ElementIndex.sourceByReference` is the file of each element (a nested element has the file of its manifest; `LayerLoader` keeps its own map across plateaus, since patches rebuild the graph); the key is the place in the element's own list after the load.
- The failure stays where it was raised, so no command that succeeds starts to fail: `LayerLoader` (layered, at the load), `GetGraphQuery.collect` (`query graph`, a relationship only: `uses` and a hosted application are not read), `KernelViewpointFactory.create` (the kernel's `dangling reference: x` and `dangling application reference: x` become the sentence when an element of the graph holds `x`; a view that names `x` keeps the kernel's words). The editor says it in `layerProblemsOf` (the file is found in `state.roots`; a workspace with no plateau is told without the plateau). Cases: `dangling-reference-cases.json`, read by `DanglingReferenceCasesTest` and `dangling-references.test.js`.
- The sentences of a view that has no element or names one that exists nowhere are one in both tools: ``the view `v` has no element: write the reference of one in `properties.element` `` (for a step with an inline recipe `v` is `step_NN`) and ``the view `v` names `gone`, which does not exist``; cases `view-problem-cases.json`, read by `ViewProblemCasesTest` and `view-problems.test.js`.
- Not aligned on purpose: an unknown viewpoint (a warning of the command line, a status of the editor); a plateau that lacks the element or the pinned entries (a warning that skips, against a status of the view; pinned by the goldens, N81, N82 and the byte-identity harness); a map pinned on missing entries (different behaviour, not different words); a facet that removes the element (told once); a layered view that names an element declared in no plateau (K04 and K05 on the command line, the same sentence in the editor's banner and the sentence above on the view's page); `This view does not exist.`, `The view “v” does not exist any more.` and `This step has no view.` (states of the page's own lists, no command-line twin).
- The byte-identity harness `scripts/byte-identity.sh` is described in `src/test/CLAUDE.md`.

## The command reference of the manual

- A change to a command, an option or its description changes the generated block of `[[command-reference]]` in `src/doc/README.adoc`, and `CommandReferenceTest` fails until it is regenerated: `ARCHICODE_MANUAL_REGENERATE=1 JAVA_HOME=<jdk 25> ./mvnw test -Dtest=CommandReferenceTest`.
