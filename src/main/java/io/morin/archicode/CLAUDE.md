# The command line (Java)

Static analysis, the workspace file, facets, errors and warnings, the schema of the manifests, the guide, init, and the reading of mistakes. Moved from the root `CLAUDE.md` with its wording unchanged; the root file says where each area lives.

Java static analysis (wave 023, run 0177, W-11, #160 step 5, decision D1): PMD 7.28.0 through `maven-pmd-plugin` 3.28.0 (both pinned in `pom.xml`, Maven Central, no server and no secret). The `check` goal is bound to `verify`, so the job `Java` of CI runs it with `./mvnw verify` and a finding fails the build; there is no baseline file (T8): a finding is fixed, or its rule is turned off in the ruleset with its count and its reason (T9). The ruleset is `src/main/pmd/ruleset.xml`: PMD's `quickstart` set minus `ControlStatementBraces`, `AvoidUsingHardCodedIP`, `LocalVariableNamingConventions` and `UselessParentheses` (Prettier writes those parentheses itself), and with the properties of four rules adjusted (`LooseCoupling`, `GuardLogStatement`, `CloseResource`, `CompareObjectsWithEquals`), each with its reason in the file. PMD needs the compiled classes to resolve types, so the one command for a developer or an agent is `./mvnw test-compile pmd:check` (without `test-compile` the findings differ); it reports in `target/pmd.xml`, and a file it cannot analyse fails it too (`skipPmdError` is false). The Native job skips it (`pmd.skip` in the `native` profile): it runs on the sources the Java job has checked. The sources the chicory compiler writes (`ViewpointKernelModule*`) are excluded. SonarLint stays the author's own choice in the IDE, outside the build. PMD resolves types with the compiled test classes, so a build that leaves them out (`-Dmaven.test.skip`) must skip it (`-Dpmd.skip=true`): the two publishing builds of the `Build` job do, because `Java` has run it on the same sources; without that skip it reported a finding on `main` that `verify` does not (`NonExhaustiveSwitch` on a switch whose type it could not resolve).

Facets (`settings.facets`) are evaluated by the same kernel, as standard JSONPath (RFC 9535, `serde_json_path`): `WorkspaceFactory` hands it the JSON of the workspace (`apply_facet`), the editor hands it the elements of the view. Jayway is still used by the `query` commands only. **The schema of the manifests** (wave 022, run 0158, #144 first step, decisions T2 and T3): `archicode query schemas manifest` no longer has `"type": "any"` for `content`. `manifest/ManifestSchema` generates it from the classes: the envelope (`Manifest`, `header` and `content`) and, under `kinds` (keyed by the `header.kind` ids), the schema of the content of each of the ten kinds, produced by Jackson's JSON-Schema generator from `ManifestKind.getType()` and completed from the classes by introspection (`additionalProperties: false` for a class that does not ignore unknown keys, `aliases` from `@JsonAlias`, `required` from `@JsonProperty(required)` or `@Required`, the rule of an id and the form of a reference from `@Identifier` and `@Reference`, an enum sorted and said to be read in any case). Each element kind also says `layer`, `holds` (the kinds it can hold, from `Parent#elementType()` and `Nesting.kindsHeldBy`) and `heldAtTheTop` (`Nesting.holdsAtTheTop`); the `elements` of a parent is a union in the `type` of its items of `{"$ref": "#/nested/<kind>"}` for the kinds it holds, and `nested` has the form of each element kind as it is written under a parent (the content plus a required `kind`), so the recursion (a node in a node) is a pointer and not an infinite tree. Nothing is typed by hand, and nothing moved in `query schemas workspace` (the new annotations are read by this schema only; `@Required` exists because adding `@JsonProperty(required)` to `View`, `Story` and `Plateau` would have moved the workspace schema, which is byte for byte that of 0.19.0, golden `src/test/resources/schemas/workspace.schema.json`). Dialect (Q1 kept): Jackson's, close to draft 3, `"required": true` on the property and no `oneOf`, so a content that depends on `header.kind` is not one schema but the ten of `kinds`, chosen by the reader of the schema; the `relationship.qualifier` singular spelling (a single text, added by Lombok's `@Singular` builder) is not in the schema, because it has no getter. What a schema cannot say is `src/test/resources/schemas/not-expressible.json` (a reference that resolves, a reference or a plateau declared twice, a `header.parent` that exists, the root of a layered workspace, the tree of plateaus, a patch that selects something, what a view or a story step names, `.archicode.yaml`, the name of a facet), one entry per limit, with the cases of `negative-cases.json` that run it. Tests: `ManifestSchemaTest` (V1: the golden file `manifest.schema.json`, the same bytes every time, the keys the Jackson reader knows), `EditorReadSchemaTest.shouldSayWhatTheEditorTableSays` (V2: the schema equals `READ_SCHEMA`: keys, required, enums, shapes, nested kinds, held at the top, lenient types), `ManifestSchemaCorpusTest` with `ManifestCorpus` and `SchemaChecker` (V3: the 421 manifests the repository ships conform, the cases of `negative-cases.json` that load conform, the structural ones are refused, every other refusal is in the table and the table has nothing else; the checker reads the subset of the dialect the generator emits) and `SchemasIT` (V5: the packaged application prints the golden files). A change to a class that changes the schema changes the golden file in the same commit; regenerate it with `archicode query schemas manifest > src/test/resources/schemas/manifest.schema.json`.
