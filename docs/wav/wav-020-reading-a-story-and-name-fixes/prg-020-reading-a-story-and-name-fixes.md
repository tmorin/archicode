## Findings

- Issue #146 was partly wrong: `ErrorOutput` never reworded a message, only the editor guessed from the text. The one real bug in the command line was a workspace file the OS refuses to read, which printed a stack trace.
- A run that adds a Java class needs `reflect-config.json` in its `likely_paths` (`NativeReflectionConfigTest`); runs 0146 and 0147 both hit it.
- W-4's note that no step sets `ref=` was too broad; steps whose view is an element's set it. Tests that compare addresses drop it.
- The save (W-3) has two older defects, filed as #150 and #151.
- The reading mode reads "puts the reader back as they were (`storyHome`)" as "changes nothing but the layout", as *Leave story* does; the author may want the plateau of before the story restored instead.

## Lessons Learnt

- A feature run is best split where the exit evidence differs: the step menu (W-4) was finished and evidenced alone, and the reading mode (W-5) reused it without touching it.
- The orchestrator's own look at the built-in browser (a hidden pane cannot take screenshots, but `javascript_exec` and `resize_window` work) found nothing the executor had not reported, and costs a few minutes.
- Carried from wave 019: brief every run with the byte-identity base in hand (a jar of the tag); a wall-clock ratio is not a gate until it has been measured on the CI runner; a manual test that reads `.adoc` makes a docs-only run need the whole verification set after its last edit.
