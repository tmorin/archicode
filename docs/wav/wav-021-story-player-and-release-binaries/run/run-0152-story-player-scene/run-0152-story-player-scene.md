# Run 0152: story-player-scene

Wave 021, W-1. The wave 020 reading mode, merged and never released, is removed (plan decision T2), and a step of a story is drawn by a scene of its own that does not touch the editor (T4), so that the player of W-2 can put it in a modal (GitHub issue tmorin/archicode#153; the commit of the wave closes it, this run does not). No Java, no Rust, no manual change; the command line is not touched (T1).

Profile `single-document`: one page, one refactor of its drawing path, one function and their tests. The plan's T2 and T4 hold the design. The review passes are answered below.

## Review passes (the trio's, answered here)

- **KDMLLC.** KISS: no snapshot, no second pipeline: one function was cut out of a closure and five readers gained one optional argument. DRY: the editor and the player draw through `computeDiagramScene`, `comparisonStateOf` and `viewDiagramRecipe`. MECE: what a scene reads (the `source`/`drawing`), what it returns, and what it never touches are three lists in decisions 4 to 6. LEAN: no new cache but a map on the existing `layerCache`, no new setting. LUCID: every new function has a doc comment saying the rule; `CLAUDE.md` says it in the stories paragraph. CONSISTENT: same words as the bar ("cannot be drawn" sentences come from `stepProblem`), same recipe as the page of a view.
- **Open questions.** The refactor or the stop (T4 allowed the stop): the reads are few and every one has the shape "this model" instead of `AppState.index`, so the refactor was made and the byte identity of the editor is tested rather than argued. The toggles (`changesOnly`, `hideWording`): the editor's, read at call time. A cache of scenes: not in this run. `readonly` default: off. Where `home` comes from: the caller.
- **C scan against the repository.** The old closure's behaviours are kept one for one: an error and a facet that removes the element are shown and not cached (`cacheable: false`); the early `seq` checks are one check after the await in the caller; the hint for an element with no relationship, the fold targets of a Map, `drawnApps` are in the core. One existing test pinned the text of `mountDiagramIfNeeded` (`styles.test.js`, the stereotype list of the key); it now reads `computeDiagramScene`, and `library-view-diagram.test.js` (the closure reads no editor global) still passes on the shorter closure.
- **Canonical impact.** `CLAUDE.md`: the reading-mode sentences of the stories paragraph are replaced by the scene and the announcer (one block, no new paragraph), and the pointer to `[[editor-reading-mode]]` says it is removed. The manual is W-6's (below). No `dom` packet, no `arc` item.

## Findings for the wave

- The scene is the same code as the editor's drawing, not a copy: any later change to the editor's drawing is a change to the player's. The test that compares them (`story-player-scene.test.js`) is the guard; it needs the harness's fake layout, so a change to the real layout is not covered.
- `storyStepScene` loads ELK and the kernel on each call (cached by their loaders), and lays out each step again: each step costs a `compute` and a layout, and a comparison step a `compare` the first time its pair is drawn. W-2 may draw the next step while the reader looks at this one, or cache by `viewKey` and the `layerCache` it fills.
- The home of the editor's walk (`storyHome`) and the player's home are two things: the player's is a plain object the caller keeps; nothing here moves `storyHome`.
- An address (`story=`, `step=`) still does not carry the comparison of the step in the editing layout (wave 020's finding, and the reason `drawStepOfReadingAddress` existed): the player's address (`play=`) draws from `storyStepScene`, which does not need it.
- Proposed commit subject: `refactor: the reading mode is removed before it ships, and a step of a story is drawn by a scene of its own that reads the model of its plateau and writes nothing (#153)`.
