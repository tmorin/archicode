## Findings

- The entanglement that T4 feared (the editor's drawing keyed on the editor's state) was a handful of reads: a small refactor (`comparisonStateOf`, a `source` option, `computeDiagramScene`) was enough, and the editor and the player now draw through the same code.
- The generated test of the save found a defect in neither issue (a comment left by a deleted line landing under a `key: |` block) and four limits that were filed (#154, #155).
- The plan's assumption that Mandrel has no macOS build was out of date (`mandrel-25.0.4.1-Final` ships `macos-aarch64`); `macos-14` is being retired (use `macos-15`).
- A dispatch from a branch works before the merge when the workflow file already exists on the default branch and carries the trigger: the rehearsal needed no merge.
- `Build` has no `permissions:` block and the repository's default token is write-all (left alone: a follow-up for the author).

## Lessons Learnt

- Opening the pull request as a draft as soon as a run changes CI (here W-4) lets the pipeline test the run while the next one is written: the native `--version` and the artifact were proven in CI before W-5 started.
- A tested script beats a long inline step: the bash 3.2 run of `test-release-scripts.sh` caught a real `set -e` trap that no review would have.
- Carried from wave 020: a feature run is best split where the exit evidence differs; the orchestrator's own look in the built-in browser (`javascript_exec`, `resize_window`) is cheap; any run that adds a Java class needs `reflect-config.json` in its `likely_paths`; a manual test reads `.adoc`, so a docs-only run needs the whole verification set after its last edit.
