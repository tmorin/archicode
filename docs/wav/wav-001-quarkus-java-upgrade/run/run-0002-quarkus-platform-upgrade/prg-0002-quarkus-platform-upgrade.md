## Lessons Learnt

- When a version bump brings a platform BOM's own transitive pins level with (or past) a prior run's hand-added Java-version-compatibility overrides, the right move is to re-derive each override from the new BOM directly (fetch the actual `-bom-<version>.pom` from Maven Central) rather than trust the old override's version number or its now-stale rationale comment — two of the four categories here were exactly redundant, one was an accidental downgrade waiting to happen, and only direct inspection caught the difference between those three outcomes.
- `./mvnw <plugin-coords>:update -N -DplatformVersion=<target> -DrewriteDryRun=true` is a safe, cheap way to preview `quarkus:update`'s actual proposed diff (written to `target/rewrite/rewrite.patch`/`rewrite.log`, both gitignored) before committing to anything — worth reaching for before hand-writing a cross-version migration from migration-guide reading alone. Re-running the same dry run after applying the changes by hand is an equally cheap way to confirm completeness ("The project is up-to-date" is the tool's own closing-the-loop signal).
