Wave 015 (`editor-reshape-and-loose-ends`), item W-16 (phase P1). Focus: move an element wherever it can go, say why a parent is not offered, and drop the path nobody can reach (#43, #44, #97)

## Decisions

- **D1. Four ways to write a move, chosen per case and told in the dialog** (`moveRouteUnder`, `moveTopVerdict`; the comment above the Move section of the page says them once):
  `header` for an element with a manifest of its own: only its `header.parent` changes (at the top level the line goes), as before; `inline` for a nested element and a parent in the same file: the block moves inside the file, as before (byte for byte, D8); `paste` for a nested element and a parent declared in another manifest of the plateau written: the block is **cut out of one file and pasted in the other** (#43, option one of the issue); `extract` for a nested element that goes to the top level (#44) or under a parent of a plateau whose files the plateau drawn does not write: the element gets **a manifest of its own** (#43, option two). Cut and paste is the rule between two files of the plateau written because it keeps the author's file as it is (the element stays where its siblings of that file are written, nothing new appears on disk); a manifest of its own is the answer only where no block can go: the top level has no `elements` to hold it, and a file of an overridden plateau is never written.
- **D2. The block is carried as it was written.** `cutBlockFromText` (the text of the file without the block, and the lines of the block with the comments just above it) and `pasteBlockInText` (those lines put as the last child of the parent, one level in or out as the parent's depth asks, with the `elements:` line that opens a list when the parent had none) are the two halves of `moveBlockInText`: same machinery (`emittedBlockOf`, `locateEmittedLines`, `openFlowLists`/`closeFlowLists`), same check at the end (the text re-read must give what the emitter writes for the new model). A flow collection inside the block goes back as written (`closeFlowLists` over the carried lines). A file whose layout they cannot follow (an anchor, an alias, a tag, a list at the column of its key) is written by the ordinary save, as the emitter writes it: the move works, the file says the right thing, the comments of the block are the price (pinned). The end of line of each file is its own (a block cut from an LF file and pasted in a CRLF one is CRLF).
- **D3. Both files are marked modified, and a refused write changes neither.** The pasted file is marked dirty in `applyMovePlan` (`commitElementEdit` marks the file of the element only); everything runs inside the mutator of `commitElementEdit`, so in a layered workspace it is under `guardedLayerWrite` (`live: true`), and `snapshotWriteState` already holds every file's text, header, content and mark and the list of files (a created manifest goes with the restore).
- **D4. The new manifest of `extract`** is made from the block (`manifestTextFromBlock`): the `- ` that opened the item goes, so does its `kind` line (it is in the header of a manifest), the lines go to the column of a `content`, the comments above the item sit where its keys are now; when the block does not have that shape or the result does not read as the model, the file is the emitter's (`serializeManifestFile`). Its header is `kind`, `version`, then `plateau` (the plateau drawn, when it is not baseline) and `parent` (none at the top level), as a new element has them (`commitCreateTopLevelElementNow`). It is written next to the file it leaves (`allocateManifestRelPath`, `app.<reference>.yaml`, `-2` when taken), `env.` for the technology layer. Cosmetic as for any new file: the kind is not quoted and there is no blank line before `content:`.
- **D5. Which kinds may be at the top: those the layer holds at its root, read from `READ_SCHEMA`** (`topLevelKindsOf`: `Application` holds person, solution and system, `Technology` an environment; a group is no root). This is what the creation form already allowed blank (`TOP_LEVEL_BLANK_ATTACH_ALLOWED`; a test says the two tables are one), and it settles the editor's half of #106: a container, a component or a node is never a root in the editor, which neither offers it nor moves an element there (`A container is never at the top level: the application layer holds only person, solution and system there.`). The command line still indexes such a root and no layer holds it: that half is for #106 and Java (out of this run). In practice the top level is offered for a system that sits in a solution; an environment, a solution and a person are there already.
- **D6. "Why not": one sentence for each element of the layer that is not offered, and for the top level** (`moveParentVerdict`, `moveTopVerdict`): the element itself, what it contains, its parent now, a kind that cannot hold it (naming what it holds), an id the parent already holds, a reference declared twice, a group under a parent of a plateau whose files are not written. The dialog lists them in a closed `<details>` under the places offered (`N places are not offered, and why`), narrowed by the same search. The same sentences are the refusals of `validateMove` (one function, so they cannot disagree); the checks that stop every move (an element inside it declared twice, a manifest that cannot be read, a reference that cannot be rewritten as text) are told once at the top of the dialog (`No move can be written now. ...`). A test checks, for every element of two layers, that the places offered and the places refused are the whole layer, each once.
- **D7. #97 (decision T1 of the plan): the second button is removed.** `planMoveReplaces`, `replacesAncestorProblem` and `replacesDirectionProblem` (only the plan used them), the `writeReplaces` option of `validateMove`, `commitMoveElement` and `submitMoveDialog`, the `data-replaces` attribute and the two buttons are gone; the dialog has one button, *Move*, and (in a workspace with plateaus) a line that says *Move* writes no `replaces` and that *Write replaces* of the Changes panel is where the key is written. `replacesWith` stays: *Write replaces* and the list of `replaces` of the form use it (so `git grep replacesWith -- src` is not empty; `planMoveReplaces` is). The result of a move is `{ ok, reference }` (no `replaces` count). The tests that stubbed `replacesAncestorProblem` lost the stub and, with it, the checks of what a move writes as `replaces`; what they pinned of the quotes and the flow lists is pinned by the same tests on a move that writes none (D8).
- **D8. A workspace without plateaus saves the moves that already worked byte for byte as before.** `move-elsewhere.test.js` holds the files that the page of the commit before this run wrote for an in-file move and a `header.parent` move (captured by running that page on the same folder), and the page now writes the same bytes. The tests of `move-editor.test.js` that pinned the in-file layouts (CRLF, comments, text over several lines, a parent with no elements, the last child leaving) pass unchanged.
- **D9. The top level is a choice of the dialog, `MOVE_TOP_LEVEL`** (a value that is not a reference: it starts with a space), listed first when offered; `commitMoveElement(reference, layer, MOVE_TOP_LEVEL)` moves there. A reference that is said by number (`destination: 8080`) still refuses, as before.
