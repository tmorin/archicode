# Run 0102: Delete a plateau

Wave 015 (`editor-reshape-and-loose-ends`), item W-14 (phase P1). Focus: delete a plateau from the page Plateaus without losing anything the author did not see listed (#93)

Document profile: `single-document`, as runs 0089 to 0101. The rule is the plan's (decision T5: only a plateau that no other plateau overrides can be deleted, after a dialog that lists every file that goes); what is left to decide is what else names a plateau and what the delete does with it, each in a line below and pinned by a test. Tier `hard_judgment` (data deletion): every task was done inline, none delegated; a read-only review of the diff was delegated (see F2).

## Scope

In: the editor (`standalone.html`: the plan of a delete, the write, the dialog, the buttons on the page Plateaus, the snapshot of a write, the settings written to `workspace.yaml`), the tests (`delete-plateau.test.js`), `CLAUDE.md` (one sentence).

Out: deleting a plateau that others override (issue #112), the command line (it deletes nothing; a plateau is files, removed by hand there), the manual and the tutorial (W-18, see F1), choosing `settings.current` in the editor (issue #111).

## Decisions

- **D1. Where.** A *Delete* button on each plateau of the page Plateaus but the root (`timelineItemHtml`) and *Delete plateau* beside *New plateau* / *Edit plateau* for the plateau drawn (`plateauWritingHtml`, `plateauDeleteButtonHtml`); both open one dialog (`openPlateauDeleteDialog`, kind `plateau-delete`). The band does not write (D2 of the wave). A plateau that others override keeps the button (its tooltip and the dialog say why it cannot go): a button that vanishes says nothing.
- **D2. What can go.** Only a plateau that no other plateau overrides (`layerChildrenOf(id)` is empty): nothing inherits what it declares or patches, so no other plateau changes with it. Refused, in one sentence: the root (``The plateau `baseline` is the root of the plateaus: every other plateau stands on it, so it cannot be deleted.``), a plateau others override (``... the plateau `marketplace` overrides it`` / ``the plateaus `a` and `b` override it``, in the order of the band, with what to do), plateaus that cannot be drawn (`layers.blocked`), a workspace with no plateau, a save in flight. A plateau the kernel cannot resolve (bad patches) can be deleted: it is a repair, and the guard compares the plateaus that stay.
- **D3. What goes, and only that.** Its manifest of kind `archicode.morin.io/plateau` (`node.manifest`, none for a plateau that headers alone declare) and every manifest whose header says its id (`node.headers`, built by `buildPlateauTreeOf`). One header names one plateau, so each of these files is the plateau's alone; a manifest of kind plateau is not counted by its header. A view or a story that says `plateau: <id>` belongs to no plateau (run 0100): it stays, and the dialog says so. A file the editor could not read is never listed nor deleted.
- **D4. Files the editor does not read.** A `.toml` or `.json` manifest (the editor reads YAML only), and a YAML file it refuses, may say `plateau: <id>` for the command line: a YAML file of several documents is refused by the editor and read by the command line (Jackson's `readValue` reads the first document). The delete does not touch them; the dialog lists the unread files and the refused files whose text has the id, and says the command line would still read the plateau if one of them names it (`plan.unread`).
- **D5. `settings.current` that names it is taken out of `workspace.yaml`.** A `current` that names no plateau stops both tools on every command, and the editor has no other place to change the key (#111), so a refusal would leave the author without a way in the editor. Taking it out (rather than writing the parent) chooses nothing for the author: the command line then uses its own default (the last plateau when the tree is one line, else it asks for `--plateau`), which the dialog says. The same holds for `current: baseline` when the last plateau goes and the workspace has no plateau left. Only those two: a `current` that names another plateau, gone already, is not the delete's to take out. Only the line of the key goes: `writeWorkspaceYaml` now writes the settings as the file has them when the settings the editor manages did not change (`managedSettingsAsRead`); before, any save of `workspace.yaml` wrote every default of the managed settings (`labels: {}`, `global-enabled: true`, ...), which a story kept in `workspace.yaml` also triggered.
- **D6. A step of a story that names it refuses the delete** (the choice the brief left open). The dialog lists the steps (the sentence both tools would say: ``the story `tour` (`file`) step 2 says `against: saas`, which is not a plateau of this workspace (...)``), offers no *Delete*, and says to change them in Stories. Not cleared, because a step told at a plateau is the author's statement of which state that part of the story shows, and no default stands for it: cleared, the step is told at whatever plateau the reader has; set to the parent, it shows another state. The story editor already has the two lists per step to choose again in one click (run 0101), and the guard refuses the same write with the same sentence (`entryProblemsOf` is in `layerDigest`). The same refusal holds for a view or a step that names an element only this plateau declares (it would exist in no plateau, run 0100), and for a step told at `baseline` when the last plateau goes. Saved views carry no plateau and no comparison (their keys are `id`, `name`, `description`, `viewpoint`, `layer`, `properties`), so no view is listed for naming the plateau itself.
- **D7. The plan is computed, not tried.** `plateauDeletion(id)` changes nothing: it builds the tree of the files that stay (`buildPlateauTreeOf`) and asks the plateau-free check of them (`entryProblemsIn`, the core of `entryProblemsOf`, which now keeps only the cache), keeping the sentences that are not said now (`blocking`). Sentences are compared through `comparableSentence`: the list of the plateaus a sentence ends with is left out, and a step that names no plateau is one mistake whether the workspace has other plateaus or none, so a step that was wrong already (`at: typo`) is not a new mistake of the delete. `judgeLayerWrite` compares the same way, which also lets a plateau be created in a workspace that has such a step (before, its sentence changed with the list and the guard refused the creation). The dialog is drawn from the plan each time.
- **D8. The write.** `commitPlateauDelete(id)` refuses what the plan refuses, then runs under `guardedLayerWrite` (spec `plateau: id`): the files leave `AppState.manifestFiles` and those on disk are queued in `pendingFileRemovals` with their `lastKnownDiskModified` (the path of a deleted element's files, `commitDeleteElementNow`); a file not saved yet just leaves the model. The disk is touched by "Save all changes" only, which checks that no queued file changed on disk since it was read and removes them with `removeEntry` (`removeManifestFile`). A draft of the text of a removed file is dropped, a selection of it too, and the marks of modified elements it declares, unless a file that stays declares the same reference (a plateau beside it may). It ends in `rebuildIndexAndRender()` (so `modelsChanged()`). `snapshotWriteState` now also keeps the plateau drawn, the comparison and `settings.current`, so a refused write (`judgeLayerWrite` finds a plateau refused that was not, or a new sentence) puts back the files, the queue, the settings and the drawing. A leaf changes no other plateau, so the question of `layer-confirm` is never asked in practice; it is wired (`again`) and tested by forcing the check.
- **D9. The fallback of the drawing.** The plateau drawn is deleted: the plateau it overrode is drawn, with no comparison (its comparison was about a plateau that is gone; `past` would silently become another pair). The plateau compared with is deleted: the plateau drawn stays, nothing is compared. Otherwise the comparison is normalised as for any change of the tree. A change is remembered (`rememberLayerChoice`) and the page lets go of what it held (`settleAfterLayerChange(false)`); the address is rewritten, not added to the history (Back to the plateau that is gone would draw nothing new: an unknown plateau leaves the one drawn).
- **D10. What the delete does not touch, said in the dialog.** The folders of views the command line generated (`<views.path>-<id>` and the folders of its comparisons) are not manifests: they stay. The browser's remembered plateau of the folder falls back like any unknown plateau.
