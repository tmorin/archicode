## Lessons Learnt

- Reusing `GetGraphQuery`'s and `GetSchemasQuery`'s existing logic in-process (extract-method, `buildGraph`/`generateSchema`) rather than shelling out to the packaged CLI as a subprocess avoided a full JVM/Quarkus bootstrap per HTTP request and kept the behavior-preservation check mechanical: the two existing test classes passing unmodified *is* the proof the refactor didn't change anything, which a subprocess-based design couldn't have offered as cleanly.
- `query schemas manifest`'s generated JSON Schema looks authoritative but is structurally too shallow to validate manifest *content* against (`content: {"type": "any"}`, a documented limitation of `jackson-module-jsonSchema-jakarta` for raw `ObjectNode` fields) — worth checking what a "schema" a repository already generates actually expresses before building a validator against it, rather than assuming it is the right validation mechanism just because it exists and is named that way.
- A repository's own nested `.gitignore` files (here, `src/test/workspaces/.gitignore`'s `/case_*/`, written for generated output directories) can silently swallow a new, deliberately-committed fixture that happens to match the same naming convention — `git status --short <path>` returning nothing for a directory you just created is a signal to run `git check-ignore -v`, not a sign that nothing needs tracking.
