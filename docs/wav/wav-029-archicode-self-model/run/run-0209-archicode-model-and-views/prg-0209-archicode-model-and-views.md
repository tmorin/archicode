## Lessons Learnt

- Read the rules that enforce the model before writing its elements: the two wrong elements came from a plan written before the nesting and relationship rules were read, and only the Stage 5 review caught them. For a model of a codebase, read the classes that hold the rules first.
- A load is not a view: both tools accepted the workspace, but one view drew the wrong boxes (`opened` on the environments). Draw every saved view and read it, not only the load.
- Count what the test means: the saved-view count must be the named entries, not every id the tool lists.
- Keep generated output out of the model folder: draw in a scratch copy and check that nothing generated stayed in the tree. The ignore line is the second guard, not the first.
- Verification commands must match the git state: a check written on `git status` breaks when the new files are untracked folders. Name the paths.
- A drift check should match what the tool writes: a YAML file named `views-x` passes a YAML-only rule, so the check has to look at folders too.
- Write each task's result into the log when the task ends. task-007's results are not in the log, and the pln asked for them there.
- Keep the independent review: a reviewer in another agent than the drafter found two S3 and five S2 errors that the drafter had not seen.
