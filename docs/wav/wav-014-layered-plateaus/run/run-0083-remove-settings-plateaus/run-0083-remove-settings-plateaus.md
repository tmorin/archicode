## Decisions

Given by the wave plan: D1 to D5, A1 to A9; none failed, none was replaced. Decided here (none contradicts the plan; each is pinned by a test):

- **D32. The removed key.** `WorkspaceFactory.read` looks at the raw tree of the workspace file before anything else: a `settings` that has the key `plateaus` (a list, an empty list, an empty value) gives `WorkspaceFactory.REMOVED_KEY`, on every command that loads a workspace (`diff`, `views generate`, `query *`, `plateau list`) and whatever else the file holds (layers beside it included: the key is told, and nothing else). The sentence, word for word:

  `` `settings.plateaus` no longer exists: a plateau is a layer now. Remove the key, write `plateau: <id>` in the header of the manifests of each plateau, and declare each plateau in a manifest of kind `archicode.morin.io/plateau` (`id`, `name`, `override`: the plateau it builds on, `baseline` when absent, and `patches` for what it changes) ``

  It names the key, says what it was replaced by, and names the two things to write. Pinned by `RemovedPlateausKeyTest` (7 commands, an empty list, the key beside layers) and by case N41 of `negative-cases.json`, M50 to M53 of `plateau-model-cases.json`. Rejected: a migration command and a transition version (D1).
- **D33. What a converted workspace looks like.** The first state of an old workspace keeps its id and its name and is **an empty layer** (a Kind: Plateau manifest) over `baseline`, which holds the old first folder's manifests unchanged (no `plateau:` header, so not one file of the first state is edited); the other plateaus override it with their patches and their new manifests, in the folder they had (`plateaus/20_to-be/`). `later` of `plateau-comparison` and `after-declared` of the harbour are siblings of the plateau they were compared with. Rejected: (a) calling the first state `baseline` (the Brightcart precedent): every sentence the tools print (`comparing to-be (To be) with as-is (As is)`), the folders of the views (`views-to-be-vs-as-is`, which the manual includes), the ids of the tests and of the manual would change, and "same plateaus, same expected results" would not hold word for word; (b) a `plateau: as-is` header on the first state's files with the root empty: edits every file of the first state (hundreds in the harbour) for no gain, and makes the root an empty plateau. The price of D33: `diff --plateau as-is` compares with the root and says `no difference`, and `views generate --plateau as-is` also writes `views-as-is-vs-baseline` (a plateau other than the root is always compared, D17 of run 0078).
- **D34. A plateau that is the root.** `diff --plateau baseline` without `--against` is the sentence of run 0078 (``the plateau `baseline` is the root of the plateaus and nothing is before it: ... Name a plateau with `--against` ``); it replaces "the plateau `x` is the first plateau and nothing is before it".
- **D35. What stays of the old words.** `settings.current` and `--plateau` on a workspace with no plateau: the sentences say ``declares no plateau (a `plateau` key in a header, or a manifest of kind `archicode.morin.io/plateau`)`` where they said ``declares no `settings.plateaus` ``.
