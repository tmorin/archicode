# Run 0076: Recursive discovery

Wave 014 (`layered-plateaus`), item W-2 (phase P1). Focus: put manifests in any folder and have them found, in the same order, by the command line and the editor (issue #73).

Document profile: `single-document`. The scope is settled by the wave plan (A7) and the issue; what the run decides is one rule (where the manifests are, in what order, what is left out, what is refused) applied by two tools, which a TDD would restate and a pln would split into tasks smaller than their briefs. The review passes are kept (KDMLLC, C scan, open questions) and answered in this file. There is no prd, tdd or pln: the task list below is the plan, and its state is the state of the run.

## Scope

An entry of `settings.manifests.paths` that ends in `/**` is read recursively by the command line (`ManifestParser`, now through the new `ManifestDiscovery`) and by the editor (`readManifestFolder`), with a deterministic order and without the folders of the generated views. An entry without `/**` reads what it read before. The Settings screen accepts the new form and refuses the malformed ones. One list of cases, `src/test/javascript/viewpoint-kernel/discovery-cases.json`, is run by a Java test and a node test.

In: the rule and its two implementations, the shared cases, the manual (a section, an example loaded by the shipped-files tests), `CLAUDE.md` (one paragraph), the served editor's list (`link`).

Out (the issue mentions them; the plan removes them in W-9, so nothing was built for them): `plateau add` and the `path` of a plateau. The `path` of a plateau is read as it was, without sub-folders, and the manual says so. Layers (`plateau:` headers, W-3 and W-4) are not in this run.

## The rule (for W-4 and W-6)

Decided here; the Javadoc of `ManifestDiscovery`, the section `[[manifests-folders]]` of the manual and the cases file say the same.

1. **Recursive entry.** An entry that ends in `/**` (`manifests/**`; `./**` is the folder of `workspace.yaml`). The folder is the entry without `/**`, normalised (segments, `.` and empty dropped). A folder that does not exist reads nothing (as without `/**`). An entry without `/**` is read as before (`listFiles` in Java, the direct children in the editor).
2. **Which files.** `.yaml`, `.yml`, `.json`, `.toml` (`MapperFormat`, `endsWith`, case sensitive). The editor reads the YAML ones and lists the others as unread. The workspace file is not a manifest of itself.
3. **Order.** The files of all the entries, each once, sorted by their path from the folder of `workspace.yaml`, written with `/`, **compared by Unicode code point** of the whole string (so `B.yaml` < `a-b.yaml` < `a.yaml` < `a/b.yaml`, and U+FF5E < U+1F600, which UTF-16 order reverses). It depends on neither the file system's order nor the locale (`localeCompare` is gone from every list of manifest files in the page); no Unicode normalisation is applied. The order of the entries does not matter.
4. **Left out below a recursive entry** (never the entry's own folder): a file or folder whose name begins with a dot; a symbolic link to a folder (never followed, so no loop; a link to a file is a file; a link that is itself the folder of an entry is followed); the folders of the generated views: a folder whose path from the workspace folder has the depth of `settings.views.path` (as written in `workspace.yaml`, not changed by `--output`), the same parents, and whose name is the last segment or begins with it and a dash (`views`, `views-to-be`, `views-to-be-vs-as-is`, `views-shop`). A views path that is `.`, empty, absolute or contains `..` excludes nothing. A path that names a hidden or a views folder itself reads it.
5. **Malformed.** `**` anywhere in an entry but as the last segment after a `/` is an error of one line, the same in both tools: `the path `<entry>` of `settings.manifests.paths` uses `**` where ArchiCode does not read it: only a path that ends in `/**` is read recursively (...). Write one path for each folder, or end the path with `/**``. `*` alone is not a pattern (a name, as before). `..` and absolute entries keep their sentence, with or without `/**`. The check is in `Plateaus.select` and `selectPlateau` (load) and in `validateManifestsPaths` (Settings, which now also refuses `..` and absolute entries with the same sentences).
6. **Duplicates.** A reference declared in two files found by a recursive read is the one line of today, with the files in the order above (the existing `failOnDuplicates`).
7. **Unreadable folder.** The command line stops with `unable to read the path <path from the workspace>`.

## Decisions

- **D1. Sort by code point of the whole relative path**, not by segment, not by UTF-16 unit, not `localeCompare`. Reason: the two tools must agree whatever the system's language; the whole-string compare is the simplest to state and to implement the same twice. The editor's own sort (`localeCompare`) changed for non-recursive entries too, since one list has one order: the order of the Files list differs only for names that differ by case or accent.
- **D2. Hidden entries are not read below a recursive entry** (files too), because a `.git`, `.idea` or `.claude` folder is common and a recursive read would fail on its first YAML file. The explicit entry can name a hidden folder. The served editor never lists hidden entries (existing rule of `EditorHttpServer`), which the manual says.
- **D3. Links to folders are never followed** below an entry: the command line skips them; the served editor skips the entries the server marks `link` (new, `EditorHttpServer.list`); a browser's File System Access API cannot tell a link, so the editor cuts a loop with `isSameEntry` against the folders it is inside of, and reads a link to another folder (the manual says so; not verified in a real browser).
- **D4. The views folders are those of `settings.views.path` as written**, at its depth (A7). `--output` and a `directory-name-template` that does not begin with it are unknown to a reader of manifests (the manual says so). Reason: the editor knows nothing of `--output`, and the same rule must hold in both.
- **D5. Two entries that find one file read it once** (key: the normalised absolute path). This changes a case that failed before: `["manifests", "./manifests/"]` was `the reference ... is declared twice` on the command line (the editor already read the folder once). No workspace that loaded before loads differently.
- **D6. `**` elsewhere is an error, `*` is not.** A folder named `**` or `a**b` could be named before and cannot be now (the manual says so).
- **D7. The `path` of a plateau is not a recursive path.** It goes to the parser as before; a `/**` there names no folder (`the folder ... of the plateau ... does not exist`), unchanged. W-9 removes it.
- **D8. The Settings screen validates with the sentences of the load.** It validated only "at least one"; the `..` and absolute refusals existed only at load (the editor then fails to open the folder). Now one function, `manifestsPathSentence`, serves both.
