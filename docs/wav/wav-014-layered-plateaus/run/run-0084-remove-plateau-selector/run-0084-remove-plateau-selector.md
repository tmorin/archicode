## Decisions

Given by the wave plan: D1 to D5, A1 to A9; none failed. Decided here (none contradicts the plan; each is pinned by a test):

- **D41. The banner of the removed key.** `workspaceProblem` looks for the key first, as `WorkspaceFactory.read` does, so nothing else of the file is told with it; the banner is `Could not read/parse workspace.yaml: ` followed by `REMOVED_PLATEAUS_KEY`, which is `WorkspaceFactory.REMOVED_KEY` word for word. One line, the heading the editor already gives to the keys of workspace.yaml that the command line refuses; the differences with the command line's `error: <sentence>` are the three documented ones (the heading in place of `error: `, no file and line, the sentence starts with a backtick so the capital does not apply). Pinned by M50 to M53 (`editorSays`) of `plateau-model-cases.json`, read by the Java test for the command line's sentence and by `plateau-model.test.js` for the banner, and by N41 of `negative-cases.json` (`editor` steps, in place of `null`). Rejected: the heading of the plateau rules (`Could not read the plateaus of workspace.yaml:` and a line break), which makes two lines of what the plan calls one.
- **D42. `settings.current` and `--plateau` without a plateau.** The page says `` `settings.current` is `x` but the workspace declares no plateau (a `plateau` key in a header, or a manifest of kind `archicode.morin.io/plateau`) `` (the constant `NO_PLATEAU` is `WorkspaceFactory.NO_PLATEAU`), under the heading of the plateau rules, as for a `settings.current` that names no plateau (N42). The editor has no `--plateau`: its nearest input is `?plateau=` in the address, and an address that names a plateau the workspace does not have draws `baseline`, without a sentence (the choice is not typed, it is an address that may be old). M54 pins the sentence in both tools; M55 pins the command line's `--plateau y` sentence and, for the editor, what is drawn. Rejected: an error banner for the address (a bookmark made before a plateau was deleted would stop opening the workspace).
- **D43. What a layered Move writes as `replaces`.** The Move dialog's *Move and write replaces* worked only on the old mechanism (`planMoveReplaces` returned "not offered" for a layered workspace); with the old mechanism gone it would have been dead code and its tests, which are the faithful-save tests of a move (quotes, flow collections, comments), would have gone with it. It now works on layers: it is offered when a plateau is compared with (the band), writes `replaces` for the element and each element inside it, and is refused with the reason of *Write replaces* when the plateau compared with is the **future** of the plateau drawn (`replacesDirectionProblem`: the key goes on the more recent plateau). It is useful where the old reference exists in the plateau compared with and not in the plateau drawn: a sibling (mode `other`), which is the case of two plateaus that do not stack. Rejected: removing the feature (the Move dialog, `options.writeReplaces`, the owners of the key, the faithful-save tests of it) because nothing in the shipped fixtures reaches it: it is real behaviour of the editor, the cost is one function.
- **D44. Two defects of the layered Move that D43 exposed (fixed here, each pinned by a test that fails on the page of `HEAD`).** (a) `rewriteInboundReferences` (run 0082) made the `replaces` of a layered workspace follow a rename, including the `replaces` of the element that was renamed or moved, which holds its own old reference; a move that wrote `replaces: [bakery.oven]` saved `replaces: [bakery.tools.oven]`, an element that replaces itself. The element renamed or moved, and what it holds, **in the plateau that is written**, are the exception (the first version of the exception skipped every owner under the renamed element, whatever its plateau: the review found that a rename in `baseline` then left stale the `replaces` of an element of a plateau above it that sits under the renamed one; `editor-writes-layers.test.js` pins the narrow form and fails on the broad one). (b) `scanMoveReferences` counted the views and stories of every plateau while the move rewrites only those of the write scope, so the dialog said "2 saved views follow" for one that does. It counts the write scope, as `rewriteSavedViewReferences` does. Tests: the whole of `move-editor.test.js` on layers (12 tests fail on the old page, among them the two sentences above), `quotes-editor.test.js` (3), `flow-collections-editor.test.js` (1).
- **D45. The Replaces section of the edit form** is offered when the plateau tree is layered (it was offered when `AppState.plateaus.length > 1`, which is the old mechanism), or when the element already says something. A reference added by hand to an inherited element is an `ADD` patch on `replaces`, as any list field (checked by hand on the layered Brightcart). Pinned by `replaces-editor.test.js` ("the edit form of an element has a Replaces section when the workspace has plateaus"; fails on the old page for a layered workspace).
- **D46. An address that names the comparison is a choice made** (run 0040, kept): `openLayers` remembers `compare=` of the address with the plateau drawn, as the code of the old mechanism did for `@baseline`; the old shortcut `@baseline` in an old bookmark is read as no comparison. The address of a removed element carries `compare=other%3A<id>` and `plateau=<id>` (the form the band writes since run 0080).
- **D47. `{ pending: true, changed }`** is the answer of `guardedLayerWrite` that asks for confirmation (it was `plateaus`), and `layerDigest().byPlateau` (was `.plateaus`): two properties of run 0082 renamed so that the key the gate greps for appears nowhere else in the page. The tests of run 0082 follow.
- **D48. `serializeManagedSettings` always writes `manifests.paths`** (it left it out for a workspace that listed plateaus and did not write it): a workspace without plateaus and a layered one saved it already, byte for byte as before.
- **D49. `comparisonState().problems` no longer has the "references declared more than once" case for the plateau compared with** (a layered `AppState.baseline` has no `duplicates`; a duplicate blocks the plateaus before they are drawn, `layersBlockedReason`), and `AppState.baseline` is `{ plateau, index, problem, undrawable }`.
