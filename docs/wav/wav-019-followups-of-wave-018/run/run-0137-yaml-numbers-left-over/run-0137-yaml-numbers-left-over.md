# Run 0137: yaml-numbers-left-over

Wave 019, W-1. The editor and the command line read a YAML number the same way in the four cases GitHub issue tmorin/archicode#136 left (rest of #103), and in the tagged scalars that issue #78 lists (decision T2 of the wave plan: the command line is the reference and is not changed; each difference is fixed when the page can do what the command line does, otherwise it stays pinned with its sentence). The page is the only thing that changes (`standalone.html`); no file under `src/main` other than the page, no kernel, no contract.

## Scope

What the command line does was measured, not assumed: the jar of the tag `archicode-0.17.0` was run on every case, and the tagged scalars were read by Jackson 2.21.7 over SnakeYAML 2.6 in a probe over every spelling of up to five characters (`!!int` and `!!float`: about a million each, over `0189_.eE+-xbXFa` and the space; `!!binary`: 1.6 million, over `AQgw+/=_ é-`) and over the long ones that decide between `int`, `long` and `BigInteger`. The page's functions (`yamlTaggedInt`, `yamlTaggedFloat`, `yamlTaggedBinary`) agree with the probe on all of them (0 differences; the probe is in the scratchpad, not in the repository, because the data is large: `yaml-number-cases.json` keeps the cases that matter).

## Decisions

- **Where the reader meets a scalar it refuses (difference 2).** Measured, and not what the issue says: the content of a manifest is decoded whole when the reader gets to it (a scalar it refuses anywhere in it, even after an unknown key, is the first thing said: `Malformed numeric value '.inf' at `content``), the header is read key by key (an unknown key is said when its value has been read, so `foo: .inf` is the unknown key, `parent: .inf` followed by `foo: 1` is the number, `foo: 1` followed by `parent: .inf` is the unknown key), and the root of the manifest is the same (`extra: .inf` is the unknown key). `workspace.yaml` is decoded whole (`foo: .inf` anywhere is the number), as the page already did. The refusal is therefore lazy for a plain number and for `!!float` (the sentence is for the place where a value is asked of it: `at `header.parent``, `at `content``, `at `header`` for a header that is the scalar, a content that is the scalar is a number: `wrong shape (found a number)`), and eager for a tagged integer and a binary text (Jackson raises them when it reads the token: under an unknown key too, `at `header`` in the header and with no place at the root). The page reads a manifest with a refused scalar held as its text and a mark in the table of plain numbers (`kind: 'malformed'`, `message`, `eager`): `parseManifestText` sets `yamlDeferMalformed`, `headerProblem` and `manifestProblem` say the sentence in the order the command line meets the keys (`firstRefusedScalarIn` for the content). `malformedNumberSentence`, which guessed the place from the lines, is gone. Rejected: a second pass that replaces the refused scalar and compares the first mistake it finds with the place of the number (the order inside the content and between header and content cannot be told from the tree).
- **A tag says what a scalar is before it is looked at as a number** (`yamlRawScalars`): the plain scalar after a tag is the text (`!!int .inf` and `!!str .inf` are texts; before, the page threw the malformed number before it applied the tag). The value the line reads as without the tag is still computed (`untaggedReadingOf`) because the save compares the tagged value with it (`changed`).
- **`!!int` is Jackson's integer, not a regular expression** (found by the probe): after a first `+` or `-`, a `0` followed by a digit or `_` is octal, `0x`/`0X` hexadecimal, `0b`/`0B` binary, and the digits are what follows with the `_` taken out; anything else is a decimal number if it is made of digits and `_`, else the text (`1:30`, `1e3`, `0o17`, `abc`, `1.5`). A number it cannot read is refused with the sentence of Java (`Invalid base-8 number ('9'), problem: For input string: "9" under radix 8`, `Invalid number ('_')`), and the digits are parsed as `int`/`long` up to 63 bits (31 for `int`, the whole string is in the sentence) and as `BigInteger` beyond, which says the group of digits it stopped at (`digitsPerInt` 30, 10, 7 for radix 2, 8, 16): the page does the same, so a long invalid number says the same group. The sign inside the digits (`0x-1` is -1) is Java's. Not read like Java: the digits of other scripts (`Character.digit`).
- **`!!float` is `Double.parseDouble`** of the text with its `_` taken out (and a first `+` when there is a `_`: found by the probe, `++0` is refused and `++_0` is 0): `12` is `12.0`, `1d`, `1f`, `.5`, `5.`, `0x1p3`, `Infinity`, `NaN` (which the content holds as the texts `Infinity`, `NaN`), `1e400` (`Infinity`); `0x1F`, `.inf`, `1:30.5` are `Malformed numeric value`. `javaDoubleText` was corrected for the numbers with one digit, where Java takes the closest of those with two (`4.9E-324`, JavaScript says `5e-324`); also true of a plain `4.9e-324`.
- **`!!binary` is Jackson's MIME decoder** (`yamlTaggedBinary`, a port of `Base64Variant.decode`, with the quirks of 2.21: no padding is a `MissingPadding` sentence, a space between two units is skipped, inside a unit it is an error), then the content holds the bytes as the base64 text (`YR==` is `YQ==`). A block scalar after the tag works (`!!binary |` over lines). Not read like Java: a code point that Java does not define (it says `Illegal character (code ...)`, the page `Illegal character 'c' (code ...)`).
- **The tagged number goes where the plain number goes** (`yamlNumberValue`, the tail of `resolveYamlPlain`, shared): a JS number when the page can hold the text Java prints for it, else the text with the mark, so every consumer (the checks of `readValue` for a whole number, a boolean and an enum, the header fields as written, the style) works as for `010` and `0x1F`. A number tagged `!!float` that is written as a whole number stays a float (`shadowing: !!float 1` is the wrong shape for both tools).
- **The save.** A tagged number is saved as written: `openYamlDecorations` read the notes in the plain mode (the number `1e3` was `'1e3'` for it and `'1000.0'` for the model, so the tag was lost); it reads them in the mode of the model now. `yamlEmittedWordsOf` finds the line of `x: 1e3` for the `1000.0` that the page holds (it did not, tagged or not: a plain `x: 1e3` was written again as `"1000.0"` when another field was edited). Checked: the save of every shipped workspace (below), and a file with every form of tag in a block list, a map and an element (`yaml-numbers.test.js`). The tags inside brackets are still written again in the editor's own layout: that is W-6.
- **Difference 4** is fixed where the style is read for the diagram (`stereotypeStyleOf`), not in `styleLookOf`: the style is copied before it is drawn and the mark is gone by then, and `styles.test.js` pins that `'1e2'` and `'2.5'` handed to `styleLookOf` are ignored. The mark is read from the entry of the workspace (`plainNumberOf`) and the value is the whole number the command line reads.
- **A tagged `!!binary` in a whole number, a boolean or an enum** is the wrong shape (found a string) for the page and `Cannot deserialize value of type `java.lang.Integer` from Embedded Object value (token ...)` for the command line, which names a Java class: pinned as the `editor` of Y226 (the shared file's own mechanism), with its reason.
