## Findings

- The Jayway-facet test of run 0138 showed that the page hid the kernel's sentence for a refused facet behind 'Nothing to show: facet removes this element' (a fourth fault, not in #137). Writing the test that goes through the view on screen found what the sentence-level tests could not.
- The plan row of W-4 said `expected-boxes.json` is rewritten; it is not, because no shipped workspace has a destination inside a deployed application across environments. The new behaviour is pinned by kernel, Java and node tests on the layered Brightcart instead.
- The plan row of W-6 said every existing save test is unchanged; three pinned the very fallback #78 removes and were updated, as the issue intends.
- `stories generate` now honours `global-enabled: false` as `views generate` does (run 0141): the one place where W-5 does not leave the 0.17.0 output as it was. It is told in the manual (`[[upgrade-0-17]]`).
- With `-Dtest=...`, Surefire also runs the `*IT` classes before `package`; after a change to the application, run `./mvnw -o package -DskipTests` first, or the integration tests meet a stale jar.
- Timing tests (`performance-budget`, `quiet-references`) fail under load when two builds run together; a budget as a ratio of two sizes in one run is steadier than an absolute ceiling.

## Lessons Learnt

- Brief a `hard_judgment` or a `standard` run with the byte-identity base in hand (a jar of the tag, a jar of the previous phase): every run that claimed 'identical' could be rechecked by the orchestrator in minutes, and two false claims of the planning phase (the behaviour of the command line on `!!binary` and on base 60) were caught earlier by running the jar.
- A gate rerun by the orchestrator on the final tree after each run, and a spot check on the part the run is most likely to get wrong (identity of the output, the quoted sentence), cost little and found nothing the runs had not reported; the reports were accurate.
- A manual test that reads `.adoc` makes a docs-only run need the whole verification set after its last edit.
