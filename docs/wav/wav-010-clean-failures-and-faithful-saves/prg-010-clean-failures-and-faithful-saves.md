## Findings

- W-1: the warnings channel prints when the command ends, so on `views generate` the warnings come after the files are written. W-2 (D-1 is (a)) needs no message path from W-1, only the kernel and the manual's facet section.
- W-1: the natural file list of a CLI run reaches `resource/**` and `reflect-config.json` (the native-image test asks for every new class); W-3 and W-2 should expect the same.
- W-3: PlantUML 1.2024.7 reads a name only up to the first character that is not a letter, digit, `_` or `.`; quoting does not help, so the fix replaces such characters by `_` (collisions get `_2`, `_3`) in `rendering/plantuml/PlantumlNames`. The conformance test and the committed views of `viewpoint-kernel/workspace` pin this naming; W-2 and W-6 regenerate them if they change how boxes are named. `render` in `ItemRenderer` and `LinkRenderer` takes a `PlantumlNames`.
- W-1, W-3: the order of `query views` and `query schemas` output is not stable between runs (#48, #49).
- W-2: a facet that removes an element now also drops the relationships, the `uses` entries and the node `applications` that name it, and the removed element's children; a reference already dangling before the facet stays an error. No warning is printed (the facet asked for it).
- W-4: the quote of a written value comes, in order, from the replaced line, its list neighbour, the majority of the lines with that key, the majority of the file, else plain; a styled result is kept only if re-reading gives the emitter's text, otherwise the old patch. Nine assertions of four existing JS test files had encoded the quote loss and were updated. The #45 reproduction does not apply to the committed `domain_plateaus` as it stands (its to-be plateau already holds the move): it needs a copy with `inventory` put back.
- W-4: `openFlowLists` still expands a one-line list into plain items, which W-5 changes; #50 (a rewritten line loses its end-of-line comment) and #51 (moving a nested element in a file with a one-line list displaces comments, same root as #41) are near W-5.
- W-5: `openFlowLists` finds each flow collection with the YAML parser itself and `closeFlowLists` puts the original text back; a collection the edit does not reach is saved as written, one it changes becomes a block. Not handled (old fallback): anchors and tags, a list at the same indentation as its key. Limits filed: #52 (a comment above a rewritten line ends up below it), #53 (a YAML 1.1 boolean word makes the save rewrite the file), #54 (an edited flow collection loses the comments inside its brackets).
- W-5: the wave plan's "list in a `- ` item" mostly already worked; the failing case was `- key: [..]` on the dash line.
- W-6: the editor's `split` is now `6 6`, the CLI's `LineStyle` 6; the CLI's `removed` (7-7), `split` (6-6) and `merged` (5-5) differ by about a pixel (#55, a decision for a release). The editor reads a `STATE_WORDS` list (`CHANGE_STATES` plus `contains-changes`).
