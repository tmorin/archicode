# ArchiCode

CLI tool (Quarkus + Picocli) for architecture-as-code: reads a `workspace.yaml` + manifests and renders C4/ArchiMate views (PlantUML).

## Build & Test

```bash
./mvnw clean install       # build
./mvnw test                 # unit tests only
./mvnw verify                # unit + integration tests (what CI runs)
```

Integration tests (Failsafe) are skipped by default (`skipITs=true` in pom.xml) unless run with `-Dnative` or on the `native` profile.

Viewpoint kernel (Rust compiled to WebAssembly, shared by the CLI and the standalone editor — see `src/main/rust/viewpoint-kernel/README.md`):

```bash
cargo test --manifest-path src/main/rust/viewpoint-kernel/Cargo.toml
src/main/rust/viewpoint-kernel/embed.sh                  # after changing the Rust: rebuilds and re-embeds the .wasm
node --test "src/test/javascript/**/*.test.js"           # kernel and standalone editor vs. the views the CLI generates
```

Maven needs no Rust: `src/main/wasm/viewpoint_kernel.wasm` is committed.

Format Java sources (no npm script is wired up, so call Prettier directly):

```bash
npx prettier --write "src/**/*.java"
```

## JDK version

This project builds and runs on Java 25 — `.sdkmanrc`, `pom.xml` (`maven.compiler.release`), and CI (`.github/workflows/ci-build.yaml`) all pin or target Java 25 consistently. There is no version drift between them to work around.

## Architecture

Entry point is a Picocli `@TopCommand` (`cli/ArchiCode.java`) with the subcommand groups `ViewsGroup`, `QueryGroup`, `EditorGroup` and `PlateauGroup` and the command `DiffCommand`. Flow:

```
workspace.yaml --> workspace/WorkspaceFactory --> manifest/ManifestParser
                 --> resource/element/{application,technology}, resource/view
                 --> viewpoint/ (view assembly: an adapter around the viewpoint kernel, Rust compiled to WebAssembly)
                 --> rendering/plantuml (PlantUML output)
```

Facets (`settings.facets`) are evaluated by the same kernel, as standard JSONPath (RFC 9535, `serde_json_path`): `WorkspaceFactory` hands it the JSON of the workspace (`apply_facet`), the editor hands it the elements of the view. Jayway is still used by the `query` commands only. An action that removes an element removes in the same step what points at it (relationships, `uses`, `applications`), so a facet can hide an element without a `dangling reference`; it is silent about it. The earlier Jayway dialect of facets (`anyof`, `noneof`, `== null`) is rewritten with a warning, until a future major version removes it.

Plateaus are layers (next paragraph; `settings.plateaus`, `plateau add` and `--baseline` no longer exist, and a workspace file that has the key fails on every command with the one `error:` line of `WorkspaceFactory.REMOVED_KEY`, pinned by `RemovedPlateausKeyTest`, and the editor says the same sentence word for word, in its banner, as `REMOVED_PLATEAUS_KEY`, pinned by `plateau-model-cases.json` M50 to M53 and case N41 of `negative-cases.json`; `Settings` has no `plateaus` property and `READ_SCHEMA` no entry for it, so the sentence for an unknown key of `settings` does not list it): `settings.current` and `--plateau` choose the plateau, and `WorkspaceFactory` loads one plateau per call (views go to `views-<plateau>`). The kernel has five entry points: `compute` (views), `apply_facet`, `apply_patches` (the patches of a layer), `states` (the seven state words, said once) and `compare` (two plateaus in, the union with a `change` on every element and relationship and a sorted table of changes out; `compute` takes that `change` back). An element of the more recent plateau may say `replaces: [ref, ...]` (references of the baseline; never guessed, read by `compare` only, kernel contract 4): it is then `moved`, `split` or `merged` and the replaced ones are no longer `removed`. `compare` also lists candidates (same kind and a name that no other removed and no other new element of that kind has, a close description or a lone sibling, the last only when one of the two plateaus is the past of the other: the host tells `compare` with `on_one_chain`, required since kernel contract 5), never applied: the CLI prints them only for a plateau that already uses `replaces`, the editor proposes them for any comparison. The computed states are `new`, `changed`, `removed`, `moved`, `split`, `merged` and, for a box that only contains changes, `contains-changes`: stereotypes added last to the box, with a default style that `styles.by-tags` overrides property by property, and given only to a box that has the state computed (the kernel says so with `contains_changes` on the item, and says the seven words once with its `states` entry point, which `KernelStates` and the page read; a hand-written state word that disagrees is only the author's stereotype, and the command says so on the error output, as it does for the warnings of `replaces`, see below). `archicode diff` and `views generate` write the table (`gap.md`, `gap.json`, with the identity and the candidates) and `views-<plateau>-vs-<against>`; the editor compares the drawn plateau with another one of the band (Past, Future or ⇄ on a node; the Changes panel with *Write replaces* and *Not related*, Changes only; there is no other selector and no *Compare to*) and moves an element under another parent (*Move*: children follow, references rewritten in every file, `replaces` written for the element and each element inside it when a plateau is compared with, and kept as the old reference through the rename). Every edit goes through the line-preserving save, and anything that changes a model must end in `rebuildIndexAndRender()` or call `modelsChanged()`: the comparison cache, the diagram cache and the cache of the quiet references are keyed on that version counter (plus the small parts that vary: facet, viewpoint, options), not on the serialised models or the kernel input (issues #32 and #37). A workspace without plateaus is byte-identical to before; `..` and absolute paths in `manifests.paths` are refused, and so is a reference declared twice. The editor reads layers (wave 014, run 0080; the only way since run 0084, which removed the plateau selector, *Compare to*, the plateau section of Settings and every read of the old key from the page): every open workspace has the band (`AppState.layers`: the plateau drawn, the comparison; `syncLayers`, `drawPlateau`, `toggleCompareWithPast`, `toggleCompareWithFuture`, `compareWithPlateau`), and a plateau is drawn as its chain, resolved layer by layer with the kernel's `apply_patches` (`resolveLayerStep`, `layerModelOf`, kept in `layerCache` for one tree of plateaus and one text of the manifests; the sentences of the checks are `LayerLoader`'s); the model of a plateau is `AppState.index`, the plateau compared with is `AppState.baseline` (the plateau drawn is the base only with the future), each record says where it comes from (`declaredIn`, `patched`) and the plateau drawn is the one a write goes to (wave 014, run 0082: `writingPlateau()`, null for a workspace that writes no plateau, which saves exactly as before): `commitElementEdit` (a field the plateau declares goes to its manifest, a field it inherits to a patch of its `Kind: Plateau` manifest, `writePatchChange` and `patchFor`: `SET`, `ADD`, `MERGE`, `SET` with `where`, one patch per target and field, new patches at the end of the list), `commitDeleteElement` (a `REMOVE` for an inherited element), `commitCreateTopLevelElement`/`createManifestEntry` (`plateau:` in the header) and `commitPlateauCreate`/`commitPlateauEdit` all run under `guardedLayerWrite`, which resolves every plateau again, keeps the write only if the plateau written gives back the edited value and no plateau is refused that was not, asks first (`layer-confirm` dialog) when other plateaus inherit what was written, and otherwise restores everything (`snapshotWriteState`); the element, view, story and plateau writers of a layered workspace go through it (not *Write replaces*, which writes the key on the new element in the manifest that declares it, and not the text editor of Files); a rename, a delete and a move rewrite only the files of the plateau drawn and of those that stand on it (`writeScopeHas`). The one thing a plateau is not written for is a kernel that refuses its patches (`readOnlyPlateauMessage`). The editor's pages (wave 014, run 0081): the perspectives are Timeline (the pages Timeline, Applications, Environments, Elements), Stories, Files and Settings (`PERSPECTIVES` gives each page its `group` and its `route`; `currentPageId()`, `pageIdFromHash`); the code still calls `map` the page Applications and `library` the page Stories, and the page Environments is Elements with `elementsScope` set to `technology` (no map of environments exists); the routes `#/map`, `#/elements`, `#/library`, `#/stories` (and `#/diagram`) still open and the page rewrites them to `#/timeline/applications`, `#/timeline/elements`, `#/stories`; the stories and views of a page are those of the chain of the plateau drawn (`layerChainSet`, `manifestEntries`; what a rename rewrites and a delete counts is `allSavedViews` and `allStories`, of every plateau), Files lists by plateau (`filesScope`, `filePlateauOf`) and warns of a plateau that disagrees with a folder named like another plateau (`filePlateauFolderWarning`).

Where the manifests are: an entry of `settings.manifests.paths` that ends in `/**` is read recursively, any other entry reads the files directly in its folder. `manifest/ManifestDiscovery` (the command line) and `readManifestFolder` in `standalone.html` (the editor) apply one rule, run on one list of cases, `src/test/javascript/viewpoint-kernel/discovery-cases.json`, by `ManifestDiscoveryTest` and `discovery.test.js`: files sorted by their path from the folder of `workspace.yaml`, compared by Unicode code point; below a `/**` path, no hidden file or folder, no link to a folder (`link` in the list of `editor serve`), and no folder of the generated views (`views.path` at its depth, and the folders beside it that begin with its name and a dash); `**` anywhere else in an entry is a one-line error (`ManifestDiscovery.pathProblems`, `manifestsPathProblems` in the page). A change to the rule is a change to the cases file.

Layered plateaus (wave 014): a manifest of any kind says `plateau: <id>` in its header (none: `baseline`, the implicit root), and an optional manifest of kind `archicode.morin.io/plateau` (`resource/plateau/Plateau`: `id`, `name`, `horizon`, `override` — one plateau, absent means `baseline` — and `patches`, read by `Patch` and carried as data for the kernel's `apply_patches`) qualifies it. `ManifestParser.parse` builds a `resource/plateau/PlateauTree` from them (ids in `[a-z0-9_-]`, declared once, a known `override`, no cycle: one `error:` line each; a plateau that only headers name, or two ids one letter apart: a warning through `Warnings`), and `PlateauTree.redeclared` refuses a reference, view or story declared in a plateau and again in its ancestor (two plateaus that do not stack may each declare it). `tree.chain(id)` is what a plateau is loaded from (root first): `workspace/LayerLoader` adds, for each plateau of the chain, the elements, views and stories of `Parsed.ofPlateau(id)` to the graph, then hands the elements of the two layers and the patches of the plateau to the kernel (`apply_patches`, a plateau without patches does not leave the model), then checks the layer (a relationship, a `uses` entry, a hosted application, a parent, and what the views and stories placed in it name must exist: one `error:` line each, naming the plateau; the first plateau that is wrong ends the load). `WorkspaceFactory.load` takes this path when the manifests are layered; `--plateau` names the plateau (default `settings.current`, else the last one when the tree is one line), `--against` the plateau to compare with (default the one it overrides; the root has none to default to), `plateau list` lists the tree, `views-<plateau>` and `views-<plateau>-vs-<against>` are the folders, and what a `REMOVE` took besides what it names (`Removal`, from the kernel's `removed` and `dropped`) is listed after the table of changes (`GapReport`, `gap.md`, `gap.json`). `PlateauComparer` leaves out of a layered target the `replaces` that the base writes the same way for the same element (an inherited element keeps the `replaces` of the layer that declared it, which would otherwise warn once per element); the `replaces` of the layers are not composed, so a move that took two steps reads as new and removed against a plateau two layers up (P4 of the Brightcart fixture). The Brightcart fixture ships only its layered form, `src/test/resources/brightcart/layered/`, written by `generate.mjs`; the converted fixtures of the old plateaus (`plateau-comparison`, `plateau-state-*`, `split-relationships`, `replaces-large-pair`, the example `domain_plateaus`) keep their first state as the manifests of the root with an empty layer of its name over it, so their numbers did not change (what the layers add: every plateau but the root is compared with the one it overrides when its views are generated, and `diff` ends with the cascade of the removals; a tree that forks needs `--plateau`). The editor builds the same tree with the same sentences (`buildPlateauTree` in `standalone.html`, `READ_SCHEMA` for the kind); `plateau-model-cases.json` is read by `PlateauModelTest` and `plateau-model.test.js`.

Errors and warnings: `cli/ErrorOutput` is the error path of every command (installed on the Quarkus `CommandLine` by `cli/CommandLineConfiguration`, and by the tests through `errorOutput.install(commandLine)`): a failure the author can act on (`ArchiCodeException`, a manifest or workspace file that is not valid or absent, a file or folder the file system refuses, a port in use; the most precise cause in the chain wins, and an `IOException` that is not about a file is a bug) is `error: <one line>` on the error output with exit code 1 and no stack trace, a usage error keeps picocli's code 2, and an unexpected exception keeps its trace. Nothing uses `log.warn` for the user, since `quarkus.log.level=ERROR` hides it: a warning goes through the `Warnings` bean (`warn`, `warnAll`), de-duplicated, and `ErrorOutput` prints it as `warning: ...` when the command ends (before the error, if it fails). Facet rewrites, a story step on an undeclared view, a skipped viewpoint, `Comparison.getWarnings()` and `StateTags` use it. The editor refuses the same manifests and `workspace.yaml` with the same sentences (`READ_SCHEMA` in `standalone.html`: the keys, shapes and kinds of each class; `EditorReadSchemaTest` compares it with the classes, so a class that gains a key fails until the page knows it; the cases both tools run are in `src/test/resources/brightcart/negative-cases.json`). `AbstractElement.replaces` is read as a `Replaces` (a set of the references that also keeps the JSON as written), which `KernelGraph` hands to the kernel, so that the kernel's warnings about a duplicate, a non-reference entry and a non-list fire from the CLI.

## Conventions

- Lombok is used pervasively: `@FieldDefaults(makeFinal = true, level = AccessLevel.PRIVATE)` + `@RequiredArgsConstructor` for DI-injected fields, `@Slf4j` for logging, `@SneakyThrows` instead of checked-exception boilerplate.
- SonarCloud is no longer part of CI (removed — see git history). Existing `@SuppressWarnings("java:S____")` annotations are inert leftovers from when it was; no new ones need to follow that pattern.

- Every file, example or fixture the repository ships is loaded by the command line and by the editor in a test. What fails today is pinned by a test that checks the author's error message (one `error:` line, no stack trace), or it is not shipped. A wave that ships such files names, in its plan, the test that does this for each form of them.

## Commit messages

Conventional Commits, no scope except on release commits: `feat: ...`, `fix: ...`, `chore: ...`. (Early history used `feature:`; that was abandoned in favor of `feat:` — don't revive it.) Release commits from `maven-release-plugin` are the only ones with a scope: `chore(release): archicode-X.Y.Z`.

## Release

Cut via `maven-release-plugin`. Commit messages use a `chore:` prefix, release commits are `chore(release): archicode-X.Y.Z`. Tag pushes trigger publishing the site to GitHub Pages: the presentation page (`src/site/index.html`) at the root, the Asciidoctor manual (`src/doc`, built to `target/generated-docs`) at `/docs/`, and the editor at `/editor/`.
